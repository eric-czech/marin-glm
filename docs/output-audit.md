# Evaluation outputs and genomic features

Source review: 27 November 2026. The catalogue now contains **545 task/panel records** in **52 collections**. This follow-up adds SpliceAI and SpliceAI2, 25 splicing dataset–target records and seven original BEND records, and a new protocol/variant on the existing OpenSplice target. It reviews the output/scoring form of every record. It does **not** claim that every underlying dataset was downloaded, every label was validated, or every partition was reconstructed.

Individual decisions, rationales, limitations and source citations are stored in `task_outputs` in [SQLite](../data/catalogue.sqlite) and [the authoring tables](../data/catalogue.json). The site's **Scored output** filter uses these decisions. They are separate from coarse task audit status, model adaptation, model output capabilities and biological features.

## What is being distinguished

| Evaluated output | Required evidence | What it does not establish |
| --- | --- | --- |
| Isolated labels / values | A supplied sequence, midpoint, exon, gene or variant has a label, value or non-positional vector. | Locating all elements across a genomic span. A vector of cell types is not a genomic position axis. |
| Sampled position labels | Selected base/token rows are scored against annotation, or latent features are aligned with token labels. | An independently held-out contiguous annotation benchmark. Display tracks and selected features need separate qualification. |
| Dense labeling | Biological labels are evaluated at successive positions across each assessed sequence. | Valid exon chains, reading phase, full genes or alternative isoforms. |
| Signal profiles | Quantitative assay values are indexed by successive genomic positions/bins. | Discrete gene annotation. One pooled interval value is a different readout. |
| Element / boundary detection | Predicted intervals/boundaries are matched to reference coordinates. | Correct linkage of all the elements into one transcript. |
| Gene / transcript structures | Connected exon/intron/coding structures are evaluated jointly. | All isoforms, abundance, UTRs, phase or transcript-end accuracy unless explicitly scored. |
| Pairwise relationships | A supplied edge, pair or condition contrast is assessed. | Reconstructing a complete graph or transcript from those edges. |
| Sequence generation / recovery | The output is nucleotide sequence or nucleotide identity. | Dense biological annotation; predicted-oracle success is not experimental validation. |
| Retrieval / selection | The model chooses/ranks supplied candidates. | Generating new sequence. |
| Aggregate / diagnostic analysis | Representation, selection, interpretation, runtime or cohort statistics are analyzed. | A held-out annotation or causal-function test. |
| Unresolved / mixed outputs | Available sources do not resolve the individual outputs or scoring cohort. | A negative conclusion about a model's capabilities. |

These definitions concern the **evaluation**, not just the model's forward pass. The same dense predictor may participate in an isolated variant benchmark, a signal benchmark, or a structure benchmark. Per-task `prediction_form`, `scoring_unit`, `position_axis`, `structure_scope`, `status` and evidence retain that distinction. Protocol variants still specify adaptation, readout, split, aggregation and matching tolerance.

## SpliceAI

The [2019 Cell paper, including STAR Methods](https://www.scn2a.org/pdf/ARTICLE%20PAP_Splicing_Cell_2019.pdf#page=17) trains a supervised dilated residual CNN on one-hot genomic sequence. Its outputs are donor, acceptor and neither probabilities at every output base. It is included as a supervised specialist, not described as a self-supervised gLM.

The reference annotation experiment scores all positions. Training uses principal GENCODE V24lift37 protein-coding transcripts on chr2/4/6/8/10–22/X/Y; 10% of training genes are held for early stopping. The test has **1,652 genes / 14,289 donor–acceptor pairs** on chr1/3/5/7/9, excluding genes with any annotated paralog. The 80/400/2,000/10,000 context values are **total flanking bases**, half on each side, around a central output region. Training uses 5,000-base outputs, so the 10k architecture receives 15,000-base training inputs. Top-k accuracy uses the known number of true sites to choose the prediction count; it is not ordinary accuracy at a fixed threshold. [Methods, pp.17–18](https://www.scn2a.org/pdf/ARTICLE%20PAP_Splicing_Cell_2019.pdf#page=17)

The lincRNA evaluation is a separate dataset: longest-exonic transcript per gene, strong GTEx support filters, **781 transcripts / 1,047 junctions**. Both experiments assess dense site labels. CFTR and LINC00467 illustrate complete boundary recovery, but the paper's cohort-level site metrics do not establish general alternative-isoform reconstruction. Known-exon inclusion is another, isolated-exon readout. [Methods, pp.18–19](https://www.scn2a.org/pdf/ARTICLE%20PAP_Splicing_Cell_2019.pdf#page=18)

Variant prediction uses a different training label set, adding GTEx junctions present in at least five people while evaluation variants occur in at most four. The catalogue separately records GTEx cryptic detection/validation, effect magnitude, observed tissue heterogeneity, population depletion, ASD/DDD burden, selected SSC cell-line validation and controlled motif perturbations. Source counts, selected sites, assessable patients, ascertainable predictions and sensitivity truth are different units. Observed tissue heterogeneity does not become a tissue-conditioned prediction capability. [Variant methods, pp.21–30](https://www.scn2a.org/pdf/ARTICLE%20PAP_Splicing_Cell_2019.pdf#page=21)

## SpliceAI2

The [2026 preprint](https://doi.org/10.64898/2026.10.08.757673) describes a supervised model with approximately 13M parameters: one-hot bases/species channels, 20 MetaFormer blocks, dense site usage, candidate junction pairs and graph-based transcript paths. Its 196,608-base input produces site scores over the central 65,536 bases and junction scores among 1,024 candidate sites. Training uses 314,745 short-read RNA-seq samples from ten mammals and 330 long-read human/mouse samples. These are source resources, not evaluated sample counts. [Methods, pp.19–24](https://assets.illumina.com/content/dam/illumina-marketing/images/genomics-research/articles/spliceai2/SpliceAI2.pdf#page=19)

The headline transcript benchmark is **352 human genes** on chr21/22. The most abundant multi-exon transcript must have twice the support of the next transcript. A reconstruction must match from **10 bp before the first splice site to 10 bp after the last**. The models for this comparison are trained on human data only to avoid ortholog leakage; they differ from the multispecies main model. The same chromosomes are described as validation chromosomes. The paper does not specify a separate third test partition. The 82% result is therefore dominant **internal splice-pattern recovery**, not TSS/TES prediction, all-isoform recall or accurate abundance for every isoform. The NOL12 top-three example is an illustration, not a cohort-wide top-three recall metric. [Fig.1b,c; Methods p.28](https://assets.illumina.com/content/dam/illumina-marketing/images/genomics-research/articles/spliceai2/SpliceAI2.pdf#page=28)

The catalogue separates the other outputs:

- **GTEx GT/AG:** 4,545 cryptic vs 573,967 null variants for detection; usage correlation uses the 4,545 positives. **GEL GT/AG:** 3,065 cryptic vs 1,775,800 null. These are variant/site readouts, not full transcript tests.
- **GTEx sQTL:** 2,385 fine-mapped vs 3,824 null variants for classification; effect correlation uses only fine-mapped variants. The PIP, effect-size and distance filters are recorded.
- **OpenSplice:** 283,121 SNVs across 599 exons. The task reuses the existing OpenSplice delta-PSI record, with a linked cohort and native-output protocol; BEND's full intervention set and macro-gene fitted readout are retained separately.
- **Tissue/disease conditioning:** 147 RBP values, 48 tissues and a distinct fine-tuning/input protocol. Tissue-pair usage, tissue-specific variant effects, SF3B1 and DM1 comparisons are separate targets. The tissue-variant comparison fits a chromosome-grouped ridge model and does not show additional benefit from the tissue-specific model predictions.
- **Population/protein/disease analyses:** depletion, protein abundance, disease-panel enrichment and score-selected GEL RNA validation are distinct observational or selected-validation endpoints. They do not become dense annotation tests.

[Variant methods, pp.28–30](https://assets.illumina.com/content/dam/illumina-marketing/images/genomics-research/articles/spliceai2/SpliceAI2.pdf#page=28), [tissue/disease methods, pp.30–35](https://assets.illumina.com/content/dam/illumina-marketing/images/genomics-research/articles/spliceai2/SpliceAI2.pdf#page=30), [population/clinical methods, pp.35–39](https://assets.illumina.com/content/dam/illumina-marketing/images/genomics-research/articles/spliceai2/SpliceAI2.pdf#page=35).

Official code confirms separate [training tensors/masks](https://github.com/Illumina/SpliceAI2/blob/1dcd2a1882a8223095e7529982ae70bcb658340a/spliceai2/dataset.py#L48-L160), the [main multispecies chromosome partition](https://github.com/Illumina/SpliceAI2/blob/1dcd2a1882a8223095e7529982ae70bcb658340a/spliceai2/train.py#L29-L37), and a [k-best path decoder](https://github.com/Illumina/SpliceAI2/blob/1dcd2a1882a8223095e7529982ae70bcb658340a/spliceai2/utils.py#L4-L35). The public checkpoint tree lists two multispecies models; gated weights were not downloaded. The paper's exact benchmark tables/splits and human-only/tissue checkpoints were not established from that tree. Source-code inspection is not an artifact recount of the RNA-seq benchmarks.

## Compact feature presentation

The default coverage columns retain **coding sequence** separately from mixed **gene elements**, **UTRs**, **translation boundaries**, **splice sites/junctions**, regulatory elements and RNA features. Separate columns identify **jointly scored gene structures** and **spliced transcript paths**. Complete-structure tasks are not repeated under every constituent element in the grouped view. Individual features remain available through **Features → Individual** and the feature filter; all feature-level evidence stays attached to the original task.

UTRs and translation starts/stops remain distinct: untranslated-region function or input context is not translation-boundary detection, and translation boundaries are not transcription start/end sites. Regulatory tasks remain grouped by relevant elements plus their evaluated output. The evidence does not support inventing a complete regulatory-program reconstruction task as a symmetric parent to isolated promoter/enhancer tests.

`task_feature_scopes` records why a CDS-associated task is a restricted target, mixed panel, boundary context, protein-only reference or derived-proteome readout. The coding-sequence column includes restricted targets and clearly hollow protein references. Whole-genome generation, mature-mRNA inputs and mixed CDS/RNA/other-region classifiers do not qualify automatically. Complete coding structures remain in the structure column; the detailed CDS filter still retrieves them.

Grouping is a presentation decision over cited task targets, not a claim of a taxonomic or biological ontology. Neither a broad gene-body tag nor a model's native dense output places a task in a full-structure column. Detailed feature associations can describe inputs or subsets as well as targets; species × feature co-annotation is still not proof of a released joint subset.

Original Evo 2 attribution remains **41 distinct tasks / 42 associations**. SpliceAI comparator use reported by Evo 2 or BEND is external SpliceAI use. SpliceAI2's new paper contributes no new original Evo 2 provenance. Collection membership, model comparisons and cohort variants must not be summed as independent evaluations.

## Original BEND follow-up

The original BEND collection is now decomposed into seven tasks. Its gene finding is dense nine-class nucleotide annotation scored by MCC, while enhancer annotation has 782 binary 128-bp bins over each 100,096-bp window. Accessibility, histone and supplied-CpG outputs are vectors over assays/cell types, rather than genomic positions. Expression-associated and clinical noncoding variants use frozen reference/alternate embedding distance. Gene finding uses protein-identity grouping; the enhancer and assay protocols use chromosome groups. [Paper §3 and Appendix A.1/A.7](https://arxiv.org/html/2311.12570v4), [pinned output dimensions](https://github.com/frederikkemarin/BEND/blob/58ad41011125cfca339d511e9b8eb536a54b582a/conf/datadims/label_dims.yaml).

Complete released BED files and the enhancer-label HDF5 were inspected. The enhancer data have 285 vectors, each length 782, with 2,685 positive and 220,185 negative bins; their chromosome groups match the paper. Gene finding has a source discrepancy: the BED has 5,977 rows and 5,974 unique transcript IDs, with three duplicated IDs within train. Paper Table 1 reports 5,976 total and 4,780/597/597 partitions, which sum to 5,974. The released train count is 4,783. Reported and measured counts are retained separately. There is no cross-split transcript-ID overlap, which does not certify coordinate or protein-homology separation. The large gene-label HDF5 was not inspected. [Recorded byte hashes and measurements](../data/bend-output-artifact-inspections.json), [released gene BED](https://sid.erda.dk/share_redirect/aNQa0Oz2lY/data/gene_finding/gene_finding.bed), [enhancer labels](https://sid.erda.dk/share_redirect/aNQa0Oz2lY/data/enhancer_annotation/enhancer_annotation.hdf5).

## Remaining evidence limits

The output review is supported for 522 records, qualified for 21 and unresolved for two composite DeepD routing panels. Qualified decisions include sampled routing/SAE interpretation, AIDO output-binning limits and composite scalar panels whose constituent identities are incomplete. Seven collections still lack decomposed task records and now carry explicit output-review limits, including the distinction between contact matrices and isolated regulatory edges. No markers are invented for these registrations. Genome annotation is future work in the inspected LRB workshop version, not an available dense task. The eight pre-existing panel-pending records remain explicitly pending; this follow-up does not erase missing manifests.

The [OpenSplice primary preprint](https://doi.org/10.64898/2026.05.22.727141) is registered alongside inspected official [canonical-site processing](https://github.com/lehner-lab/OpenSplice/blob/3e4ad8c037c216b952f1a8945f8f498669bff589/benchmarking_predictors/scripts/processing/process_spliceai_genome_outputs.py#L1-L16). Its full preprint returned HTTP403 here; no full-paper audit is claimed. BEND and SpliceAI2 still provide explicit, independently inspected descriptions of their respective OpenSplice evaluation protocols.

No ID/OD policy, exhaustive taxonomic absence claim or model ranking is introduced by this classification review.
